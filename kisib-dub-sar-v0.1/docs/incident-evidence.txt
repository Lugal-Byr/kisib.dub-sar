LOCAL INCIDENT LOOKUP
Versioned data/certificate-incidents.json retains source, publication date, review time and documented/to test tags.
The initial Google report records historical .gh, .sl and .as namespace context, issuer-revocation reporting and Chrome's reported action.
It does not publish certificate hashes. The initial hash list is empty by design; complete incident identity is unknown.
Find hash uses a complete certificate SHA-256 and current inventory occurrences. MISS is visible and never means safe.
Additional sourced hash records can be maintained in the data file; this is not certificate store import.
Namespace matches are historical context, never proof that a newly presented certificate is unauthorized.
Registry geography, subject C=, issuer C= and CA-owner country remain separate. A ccTLD code is not a certificate-country join.
File, graph and field bounds reject malformed catalogs. Limits are resource bounds, not a 10000-record truncation.
The catalog is a dated local research record, not an authenticated live threat feed. No update service is implemented.

MANUAL TLS CHECK
Enter a DNS hostname and click Inspect TLS. One connection uses the canonical hostname and port 443.
The check makes no HTTP request and sends no application credentials or client certificate.
Windows may contact chain/revocation services and maintain its normal caches. VPN, proxy and browser paths can differ from this direct connection.
Microsoft term: SslStream.AuthenticateAsClient [documented].
https://learn.microsoft.com/en-us/dotnet/api/system.net.security.sslstream.authenticateasclient?view=netframework-4.8.1
OS-selected protocols, revocation checking requested, and a per-stream validation callback that rejects every supplied certificate error.
Microsoft term: RemoteCertificateValidationCallback [documented].
https://learn.microsoft.com/en-us/dotnet/api/system.net.security.remotecertificatevalidationcallback?view=netframework-4.8.1
No global callback, certificate-validation override or Windows trust-store mutation is introduced.
An overall 15-second wait deadline and Cancel check bound the operation's waits. Platform DNS/Schannel cleanup can outlive a canceled wait; no late callback changes the sealed result.
Failed connect, timeout, cancellation and missing certificate each remain incomplete evidence. None becomes a certificate-block claim.
No browser session is intercepted, and no browser's verifier is invoked by this check.

PEER AND CHAIN
Retain exact full peer certificate DER and each returned X509ChainElement's DER and status.
Subject/issuer CN, full DN in Details, both certificate hashes and complete-SPKI SHA-256 come from the presented certificate.
The supplied Windows chain is shown in its returned order; no hash-derived parent links or invented issuer-store paths.
Microsoft term: X509ChainElement.ChainElementStatus / X509ChainStatusFlags [documented].
https://learn.microsoft.com/en-us/dotnet/api/system.security.cryptography.x509certificates.x509chainstatusflags?view=netframework-4.8.1
Revoked is attached to the element that reports it. Unknown/offline remains unknown.
No reported revocation error is not proof that fresh online revocation information was retrieved.
This optional SslStream chain display does not implement the planned CertGetCertificateChain multiple-simple-chain bracket.
