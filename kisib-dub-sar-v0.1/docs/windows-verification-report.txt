Reproduced and repaired findings
Owned fixtures ran on both Windows architectures before and after repairs.
Baseline: 1 assertion passed; 6 failed. Hardened build: all 7 passed.
Baseline evidence:
https://github.com/Lugal-Byr/kisib.dub-sar/actions/runs/37676903719

1. Archive link traversal. A preplaced journal hardlink changed an owned
   outside sentinel; an archive directory symlink caused writes in its target.
   Directory handles now pin ancestors without delete sharing. Opened files
   are checked for object type, reparse/link attributes and final path before
   reading/writing. Both exploit fixtures leave target data unchanged.
2. Invalid pages. Negative and overflowing history page values were accepted.
   They now fail explicitly instead of reading incorrect pages.
3. Hostile retained schema. Hash-valid JSON with null reference entries was
   accepted as normal evidence and could crash its detail formatter. It now
   becomes a visible retained-evidence error, with defensive reference handling.
4. Allocation attack. A 9 MiB malformed row was fully copied to the history
   display. Oversized rows now produce a bounded visible marker, preserving
   original bytes and the following record. Object/country/bookmark reads are
   bounded before allocation; total certificate count is not truncated.

Additional corrections and hardening
The old Framework EventBookmark constructor/property calls did not compile.
They now use fixed-type, size-bounded DataContract serialization, without
BinaryFormatter. DTD/external resolution is prohibited.

Adding the callback PREDEFINED flag to physical-store requests caused
E_INVALIDARG throughout the machine. Requests now follow Microsoft's sample
and pass location flags; callback flags still identify returned predefined stores.

Dedicated system logging now lets ETW allocate its session GUID, avoiding the
reserved NT Kernel Logger GUID. Native ETL reads are protected by validated
archive handles. Existing/shared sessions are not commandeered.

Event Viewer is opened through absolute system mmc.exe and console paths with
shell execution disabled, avoiding current-directory search and .msc associations.
CI actions are pinned to the exact revisions exercised and have read-only
repository token permissions; checkout credentials are not persisted.

Every ordinary journal row reaches the OS immediately. Outstanding rows sync
on the next one-second timer tick under normal scheduling, and at close.
CAPI2/label/scan commits synchronously flush before returning. This keeps the
continuing per-event log; snapshots do not replace it. Measured initial GUI
inventory improved from 161 seconds / a 180-second timeout to 29/34 seconds.
Scheduling delays, storage failure and sudden power loss can still affect the
latest ordinary rows. Crash/power-loss/race stress across all deployments is pending.

Remaining boundaries
Requested Enabled/Blocked groups are annotations, not OS trust enforcement.
Native chain display, CTL policy/status, full CCADB ingestion/owner standings,
DNSSEC, country-wide routing controls and universal browser/private verifier
coverage remain planned functions. A certificate's country/owner label does
not prove political control or active use.

CAPI2 covers Windows diagnostics and available retained source logs. Syscall
records do not themselves identify a certificate purpose or reliable whole
application-to-authority chain. The app has no always-on service or gapless
ETL rotation; a capture has a visible 512 MB sequential ceiling. Forced-kill
orphan recovery, durable rotation and full long-run tracing stress remain pending.

Local SHA hashes detect mismatched objects, not a malicious actor who rewrites
both journal references and evidence. This is not a signed/tamper-proof archive.
Only owned local fixtures and disposable runners were tested; no third-party
systems were attacked. External professional audit, supply-chain signing,
privileged boundary/race review and manual Home/Pro acceptance remain pending.
